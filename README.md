# Git Commit Assistant

Расширение VS Code предлагает сообщение коммита по **подготовленным (staged)** изменениям Git. Оно работает локально: внешний AI API, ключ и интернет не нужны. Сообщение можно отредактировать перед применением.

## Установка с GitHub

Нужны VS Code 1.100 или новее и Git. Node.js и npm для установки не требуются.

1. Откройте [страницу репозитория Inzorum/git-commit-assistant](https://github.com/Inzorum/git-commit-assistant) на GitHub.
2. В списке файлов нажмите [git-commit-assistant-0.4.4.vsix](https://github.com/Inzorum/git-commit-assistant/blob/main/git-commit-assistant-0.4.4.vsix), затем на странице файла нажмите **Download raw file** (значок скачивания). Сохраните именно файл `.vsix`; архив из меню **Code → Download ZIP** для установки не нужен.
3. Откройте VS Code и нажмите **Ctrl+Shift+P**.
4. Выберите **Extensions: Install from VSIX...** и укажите скачанный `git-commit-assistant-0.4.4.vsix`.
5. Откройте папку Git-репозитория и пользуйтесь командами расширения. Если проект находится в WSL, устанавливайте расширение из окна VS Code, подключённого к WSL.

## Как пользоваться

1. Подготовьте нужные изменения через панель **Source Control** или команду `git add`. Плагин анализирует только подготовленные изменения.
2. Нажмите **Ctrl+Shift+P** и выберите **Git Commit Assistant: Предложить сообщение коммита**.
3. Выберите подходящий вариант и проверьте текст в поле редактирования.
4. После подтверждения по умолчанию откроется терминал и выполнится `git commit`. Результат команды виден там же.

Другой способ применения сообщения можно выбрать в [настройках](#настройки): подготовить команду в терминале для запуска по Enter либо вставить текст в поле коммита VS Code.

## Возможности

- Анализирует только изменения, которые попадут в следующий коммит: добавленные, изменённые, удалённые и переименованные файлы.
- По умолчанию определяет формат по последним 30 коммитам текущего репозитория. Доступны Conventional Commits, префикс области, квадратные скобки и заголовок без префикса.
- Предлагает тип и краткий заголовок по локальным правилам: документация → `docs`, тесты → `test`, новые исходные файлы → `feat`. Для кода дополнительно анализирует подготовленные изменения: может распознать от одной до трёх новых функций, замену магического числа именованной константой, переименование переменной и имя затронутой функции. Например: `feat(auth): add ParseArgs function to login`.
- Для неоднозначных изменений кода показывает несколько вариантов (`update`, `extend`, `fix`, `refactor`) в выбранном формате коммитов. Подсказки поясняют, когда уместен каждый вариант; смысл правки пользователь уточняет сам.
- По умолчанию после подтверждения текста запускает `git commit` во встроенном терминале. Можно переключить режим на готовую команду с запуском по Enter или вставку текста в поле Source Control. Если в последнем режиме встроенное расширение Git недоступно, сообщение копируется в буфер обмена.
- Показывает статистику подготовленных файлов, добавленных и удалённых строк, категорий файлов и применённых предложений за выбранный период.
- Позволяет менять формат, язык, область, тип по умолчанию, максимальную длину и параметры статистики через настройки VS Code.

Расширение не отправляет код в сеть. В режиме `terminalAuto` оно запускает коммит после подтверждения текста; результат команды Git смотрите в терминале. Статистика применений показывает, сколько раз сообщение было передано в терминал или поле Git, а не число успешных коммитов.

## Пример

Подготовлены `src/auth/login.ts` и `tests/auth/login.test.ts`. В новом репозитории команда предлагает, например, `chore(auth): update login`. В окне редактирования пользователь меняет заголовок на `fix(auth): reject empty password on sign-in`, после чего терминал выполняет `git commit` с этим сообщением. Если в истории репозитория преобладает формат с областью перед двоеточием, предложение будет иметь вид `auth: update login`.

## Команды

| Команда | Результат |
| --- | --- |
| `Git Commit Assistant: Предложить сообщение коммита` | Выбор и редактирование сообщения для подготовленных изменений |
| `Git Commit Assistant: Показать статистику` | Панель с текущими изменениями и историей применений |
| `Git Commit Assistant: Открыть настройки` | Все параметры расширения в Settings |

## Настройки

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `gitCommitAssistant.commitMode` | `terminalAuto`, `terminalManual`, `scm` | `terminalAuto` |
| `gitCommitAssistant.analyzeDiff` | `true`, `false` | `true` |
| `gitCommitAssistant.format` | `auto`, `conventional`, `scope`, `bracket`, `plain` | `auto` |
| `gitCommitAssistant.language` | `ru`, `en` | `en` |
| `gitCommitAssistant.scopeMode` | `auto`, `none` | `auto` |
| `gitCommitAssistant.defaultCodeType` | `chore`, `feat`, `fix`, `refactor` | `chore` |
| `gitCommitAssistant.maxSubjectLength` | 30–120 символов | 72 |
| `gitCommitAssistant.statisticsEnabled` | `true`, `false` | `true` |
| `gitCommitAssistant.statisticsDays` | 7, 14, 30, 90 дней | 14 |
| `gitCommitAssistant.showStatisticsAfterSuggestion` | `true`, `false` | `false` |

Настройки можно менять для всех проектов или отдельно для рабочего пространства в **Settings → Extensions → Git Commit Assistant**.

В интерфейсе VS Code варианты названы по-русски; технические значения из таблицы используются только в `settings.json`.

В режиме `terminalAuto` после подтверждения сообщения открывается терминал в выбранном репозитории и запускается `git commit`. В режиме `terminalManual` команда появляется в терминале без запуска: проверьте её и нажмите Enter. В режиме `scm` сообщение попадает в поле Source Control, а коммит выполняется обычной кнопкой VS Code.

## Как устроена статистика

При открытии панели плагин заново читает подготовленные изменения выбранного репозитория. Число добавленных и удалённых строк определяется командой `git diff --cached --numstat`; строки в бинарных файлах не подсчитываются. После передачи сообщения в терминал или поле Git сохраняется небольшая запись: дата, репозиторий, выбранный тип, количество файлов и строк. История хранится в `workspaceState` VS Code и ограничена 500 записями. Содержимое файлов и текст сообщений не сохраняются.

## Ограничения локальных правил

Плагин может определить тип файла, характер изменения в Git, отдельные шаблоны в подготовленных изменениях и распространённый формат заголовка в истории проекта, но не способен надёжно понять смысл произвольной правки. Если перечисление новых функций слишком длинное, плагин сначала убирает из заголовка имя файла; если и это не помогает или новых функций больше трёх, используется общее предложение. Если изменения не подходят под известные признаки, используются имена функций или файлов и несколько нейтральных вариантов. Для исходного кода всегда проверяйте и при необходимости исправляйте тип и текст. При отсутствии понятного преобладающего формата используется Conventional Commits. Проект должен быть открыт как папка VS Code, а Git должен быть доступен в среде, где запущено расширение. Основание для выбора форматов описано в файле `docs/commit-style-research.md`.

## Для разработчиков

### Запуск из исходников

Нужны Node.js 20+ и npm. Перейдите в терминале в папку расширения, где находится `package.json`, установите зависимости и откройте эту папку в VS Code:

```bash
npm install
code .
```

Нажмите **F5** и выберите **Run Git Commit Assistant (npm)**. Перед запуском расширение соберётся, затем откроется отдельное окно **Extension Development Host**. В нём откройте Git-репозиторий и вызовите команду плагина. Для отладки поставьте точку останова в `src/extension.ts`.

Если npm недоступен, но установлен VS Code Server с Node.js и TypeScript, выберите конфигурацию **Run Git Commit Assistant (offline)**.

### Сборка и упаковка

После установки зависимостей:

```bash
npm run check-types
npm run compile
npm run package
```

Последняя команда использует `@vscode/vsce` и создаёт `git-commit-assistant-<версия>.vsix`.

Если npm недоступен, но установлен VS Code Server с Node.js и TypeScript, можно собрать и упаковать проект локально:

```bash
bash scripts/build_offline.sh
python3 scripts/package_offline.py
```

Это запасной способ сборки. При наличии npm используйте основной путь через `esbuild` и `vsce`; он также запускает проверку типов.

### Структура

```text
git-commit-assistant/
├── .vscode/launch.json, tasks.json  # Отладка по F5
├── src/extension.ts                 # Команды и активация
├── src/git.ts                       # Анализ подготовленных изменений Git
├── src/diff.ts                      # Признаки в подготовленных изменениях
├── src/terminal.ts                  # Запуск Git в терминале
├── src/suggestions.ts               # Локальные правила
├── src/statistics.ts                # Сохранение и визуализация
├── package.json                     # Манифест и настройки VS Code
├── tsconfig.json                    # TypeScript
├── esbuild.mjs                      # Сборка в out/extension.js
└── .vscodeignore                    # Состав пакета VSIX
```

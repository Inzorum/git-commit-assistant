# Обзор стиля коммитов

26 октября 2026 года просмотрены доступные страницы истории основной ветки семи популярных проектов на GitHub. Сравнивались заголовки примерно первых 30–35 записей на каждой странице; служебные слияния и релизы при выводе о стиле не учитывались. Это небольшая выборка, а не правило для всех репозиториев. Доступные страницы в момент просмотра показывали записи сентября 2026 года.

| Проект | Преобладающий вид заголовка |
| --- | --- |
| [VS Code](https://github.com/microsoft/vscode/commits/main/) | Область перед двоеточием, иногда заголовок без префикса |
| [Node.js](https://github.com/nodejs/node/commits/main/) | Подсистема перед двоеточием |
| [Angular](https://github.com/angular/angular/commits/main/) | Тип и необязательная область по Conventional Commits |
| [Vite](https://github.com/vitejs/vite/commits/main/) | Тип и необязательная область по Conventional Commits |
| [Vue](https://github.com/vuejs/core/commits/main/) | Тип и область по Conventional Commits |
| [React](https://github.com/react/react/commits/main/) | Область в квадратных скобках |
| [TypeScript](https://github.com/microsoft/TypeScript/commits/main/) | Чаще заголовок без префикса |

Во всех этих стилях человек обычно пишет короткое действие и конкретный объект изменения. Форма префикса зависит от проекта. Поэтому в плагине выбран режим `auto`: он смотрит 30 последних заголовков **текущего локального репозитория** и использует преобладающий формат. Если истории ещё нет или явного преобладания нет, применяется Conventional Commits. Любой формат можно задать вручную в настройках.

Локальные правила используют названия staged файлов и модулей, но не выдумывают назначение изменения. Например, плагин может предложить `chore(auth): update login`; точное описание вроде исправления проверки пароля пользователь добавляет при редактировании.
